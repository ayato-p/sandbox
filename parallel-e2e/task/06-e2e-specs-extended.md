# 06: E2E specファイル — 拡張シナリオ（11〜20）

## 実装すること

`e2e/demo-api-e2e/specs/` に追加の E2E テストシナリオ 10 本を作成する。データ駆動テスト、詳細フィールド検証、複数シナリオ等、多様なパターンを含む。

### spec ファイル一覧

11. **`11_weather_fukuoka_tomorrow.spec`** — 福岡・翌日予報
    - スタブ: fukuoka, 2026-06-11 → 晴れ時々曇りレスポンス
    - レスポンスの日付フィールドが正しいことを検証

12. **`12_weather_sendai_past_date.spec`** — 仙台・過去日付
    - スタブ: sendai, 2025-01-01 → 過去日付のレスポンス（or エラー）
    - 過去日付のハンドリングを検証

13. **`13_weather_data_driven.spec`** — データ駆動テスト
    - Gauge データテーブルを使用
    - 複数のリージョン/日付/天気の組み合わせを1つの spec でテスト

14. **`14_weather_response_fields.spec`** — レスポンスフィールド詳細検証
    - スタブ: chiba, 2026-06-14 → 全フィールド入りレスポンス
    - 各フィールド（気温、湿度、風速、天気、リクエストタイムスタンプ等）を個別に検証

15. **`15_weather_naha_typhoon.spec`** — 那覇・台風
    - スタブ: naha, 2026-06-15 → 台風レスポンス（特殊気象条件）
    - 特殊な天気状態の表示を検証

16. **`16_weather_hiroshima_humidity.spec`** — 広島・湿度検証
    - スタブ: hiroshima, 2026-06-16 → 高湿度レスポンス
    - 湿度関連フィールドの値域を検証

17. **`17_weather_kyoto_temperature.spec`** — 京都・気温検証
    - スタブ: kyoto, 2026-06-17 → 高温レスポンス
    - 最高気温・最低気温フィールドを検証

18. **`18_weather_yokohama_wind.spec`** — 横浜・風速検証
    - スタブ: yokohama, 2026-06-18 → 強風レスポンス
    - 風速・風向フィールドを検証

19. **`19_weather_kobe_weekly.spec`** — 神戸・複数日付（テーブル駆動）
    - Gauge データテーブルを使用
    - 同一リージョンで異なる日付を複数リクエストし、それぞれ検証

20. **`20_weather_multi_region.spec`** — 複数リージョン一括テスト
    - 1 spec 内に 3 つ以上のシナリオ（異なるリージョン）
    - 各シナリオで異なるリージョンのスタブを登録・検証

### 追加ステップ実装

- データテーブル対応のステップ（テーブル行ごとの検証）
- フィールド値域検証ステップ（数値範囲チェック等）
